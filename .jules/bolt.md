## 2025-05-12 - [DayOfYear_To_MonthAndDay Loop Elimination]
**Learning:** `SolarGeometry.DayOfYear_To_MonthAndDay` is called intensively within inner loops across thousands of items (e.g., in Raytracing and ThermalSystem where O(N) lookup occurs within O(8760) loops). The default implementation iterated an array sequentially up to 12 times to find the month, wasting massive CPU cycles across large simulations. Also `Math.Floor(hour / 24d)` added unnecessary double casting and floating point operations when `hour / 24` accomplishes the same integer division safely.
**Action:** Replace iterative time calculations with precomputed O(1) arrays (`DayToMonth[365]`) and replace `Math.Floor(double)` with integer division `int / int` anywhere heavily looped logic happens. When handling potentially negative values, ensure true modulo behavior in C# by doing `((val % max) + max) % max`.
