## 2025-05-12 - [DayOfYear_To_MonthAndDay Loop Elimination]
**Learning:** `SolarGeometry.DayOfYear_To_MonthAndDay` is called intensively within inner loops across thousands of items (e.g., in Raytracing and ThermalSystem where O(N) lookup occurs within O(8760) loops). The default implementation iterated an array sequentially up to 12 times to find the month, wasting massive CPU cycles across large simulations. Also `Math.Floor(hour / 24d)` added unnecessary double casting and floating point operations when `hour / 24` accomplishes the same integer division safely.
**Action:** Replace iterative time calculations with precomputed O(1) arrays (`DayToMonth[365]`) and replace `Math.Floor(double)` with integer division `int / int` anywhere heavily looped logic happens. When handling potentially negative values, ensure true modulo behavior in C# by doing `((val % max) + max) % max`.

## 2025-05-13 - [Multidimensional Array Cache Locality in UTCI]
**Learning:** In C#, 2D arrays `double[,]` are stored in row-major order. Iterating `[probe, hour]` when the array is `[hour, probe]` causes a cache miss on nearly every access for large probe sets, as each access jumps across memory. Swapping the loop order to `[hour, probe]` (Parallel by hour) ensures contiguous memory access, resulting in a ~3-5x performance gain for large simulations.
**Action:** Always align nested loops with the memory layout of the data structure. For `[8760, N]` arrays, parallelize by the first dimension (hour) and iterate the second dimension (probe) in the inner loop to maximize cache-line hits. Renaming progress variables (e.g., `processedProbes` to `processedHours`) ensures the reporting logic matches the new parallelization grain.

## 2025-05-14 - [Annual MRT Calculation Hoisting]
**Learning:** In `EddyLib/OutdoorComfort/MRT.TwoPhaseDDS.cs`, the `SolarGain.ERF` method was called inside a nested loop [8760, N_probes]. This method performed redundant `Get_fp` table lookups and `Math.Sin` calculations for every probe, even though these values are constant for a given hour. Hoisting these calculations out of the inner loop eliminates O(N_probes) redundant operations per hour, which equates to millions of unnecessary calls in annual simulations.
**Action:** Identify and hoist any calculations that are invariant to the inner loop dimensions (e.g. per-hour solar geometry in per-probe loops). Use specialized methods (e.g. `ERF_Optimized`) to pass precomputed values into the hot path to avoid re-evaluating the same logic millions of times.

## 2025-05-15 - [Temporal Wind Factor Cache Locality and Transposition]
**Learning:** In `WindFactorsTemporal.CalcWindFactorsTemporal`, iterating over 8760 hours inside a per-sensor parallel loop caused massive cache misses due to the large stride of the `ValuesTemporalAtProbingHeight[hour, sensor]` array. Additionally, the `WFSpatial[sensor, direction]` input array had poor locality in the inner loop.
**Action:** Parallelize the temporal loop by hour and iterate sensors in the inner loop. To ensure the inner loop remains efficient, transpose the `WFSpatial` input once before the main loop to `[direction, sensor]`. This ensures both read and write operations in the hot path are sequential, leading to significant performance gains (~30%+) for large probe sets.
